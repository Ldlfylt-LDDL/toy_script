# SimCompanies 最优产业链分析

## 游戏约束

### 1. 建筑限制
- 每种建筑类型有**数量上限**
- 同一建筑可生产多种产品，但**同一时间只能生产一种**
- 建筑可以无限升级，但升级费用随等级指数增长
- → 结论：可用的"生产槽位"数量有限，产业链的**宽度（涉及不同建筑类型的数量）越小越好**

### 2. 目标：深度高、宽度窄
- **深度**（Layer层级）越高越好：意味着更多的垂直整合，每个中间环节都是竞争壁垒
- **宽度**（涉及建筑种类数）越少越好：减少建筑占用，降低资本投入
- 理想产业链：**沿一条细长的纵向路径延伸**，而不是横向扩散

### 3. 上下游产量匹配（流量平衡）
- 产业链中，上游产出量应与下游需求量**大致匹配**
- 若 A → B，但B的需求量只有A产出量的1/10，则：
  - A的大量产能被浪费，或需要同时销售A
  - 建筑升级投资回报不对称
- → 需要计算每条边的**流量比（consumption ratio）**，筛选出上下游需求比例接近1:1的链条

## 评分指标（当前版本）

### 单产品评分：`L × I`
- `L`：该产品距唯一根节点 Power(L0) 的最长路径层数
- `I`：完整依赖树中的中间节点数量（排除 Power 和产品本身）
- `R = 1`（Power 是唯一真L0，故分母固定为1，省略）

### 当前Top排名（以Power为唯一L0）
| 排名 | 产品 | L | I | 分数 |
|------|------|---|---|------|
| 1 | Orbital Rocket Assembly | 8 | 34 | 272 |
| 2 | Sub-orbital Rocket | 8 | 29 | 232 |
| 12 | Pork Dinner | 9 | 15 | 135 |
| 16 | Hamburger | 9 | 14 | 126 |
| 19 | Apple Pie | 8 | 13 | 104 |
| 20 | Lasagna | 8 | 13 | 104 |

### 指标的局限性
- 当前指标不惩罚宽度（涉及建筑种类多）
- 当前指标不考虑流量匹配（上下游产量比）
- 航天类产品分数高，但宽度极宽（需要多种建筑），实际可行性低
- 食品类分数较低，但宽度窄、流量匹配好，可能更适合单人运营

## 决策框架

### 核心约束（修正版）

- **每个产品对应一个专属建筑**，不在同一建筑内切换产品（避免运营复杂度）
- **总建筑数预算：10 ~ 16 个**
- 因此：整条产业链涉及的**产品总数（含所有中间品）≤ 10~16**

### 核心问题的重新定义

> **在 N 个建筑槽位的预算内（N=10~16），从产品图中选出一个连通子图，使得从 Power 到最终产品的深度最大，同时每条边的流量比合理。**

这是一个有约束的**最长路径选取问题**（类背包问题）：
- 每个中间节点消耗 1 个建筑槽位
- 若某产品有多个原料（分叉），每个原料也各占 1 个槽位
- 目标：N 个槽位内，最大化从根到目标产品的层数

---

### 维度一：节点预算（Node Budget）

总建筑数 N = 10~16，规划时可按 **N=12** 作为基准。

每条产业链从 Power 出发，完整依赖树中的**产品节点总数**必须 ≤ N。

| 链条结构 | 产品节点数 | 占用建筑数 | 备注 |
|---------|-----------|----------|------|
| 纯线性 5层 | 5 | 5 | 最省，剩余槽位可做其他产品 |
| 每层2个原料 × 5层 | ~10 | 10 | 接近上限 |
| 每层3个原料 × 4层 | ~12 | 12 | 到达上限，无冗余 |
| 航天类完整链 | 30+ | 30+ | 远超上限，必须部分外购 |

**结论**：原料数多（分叉多）的产品，必须有部分中间品从市场外购，不能全部自产。

---

### 维度二：自产 vs 外购的边界决策

当链条中某中间品的原料在 N 内放不下时，需要决定哪些节点"切断"（改为市场外购）：

**核心原则：部分垂直整合是完全合理的。**

> 若 A、B、C → D，其中 A 和 B 自产会导致大量过剩，那么从市场外购 A、B，只自产 C → D 这一段，是完全可接受的策略。
> 目标不是"最大化自产率"，而是"在自产的每一段链条里，最小化过剩"。

**核心约束：建筑升级是指数成本**

建筑升级费用随等级指数增长，因此上下游建筑的**等级倍数差**是关键指标，而不仅是产能浪费率。

**利用率与所需等级倍数的关系**：

在双方同等建筑数量下，若 A → B，利用率 = `(rate_B × q) / rate_A`

| 利用率 | 含义 | B需要是A等级的倍数 | 建议 |
|--------|------|-------------------|------|
| ~1.0 | 完全对齐 | ×1（同等级） | 自产 ✓ |
| ~0.5 | A有一半过剩 | ×2 | 可接受，升B即可 |
| ~0.25 | A有3/4过剩 | ×4 | 勉强接受 |
| ~0.1 | A有9/10过剩 | ×10 | **不可行**，指数成本差距过大 |
| < 0.2 | 严重失衡 | >×5 | **改为外购** ✗ |

**直觉规则**：若 A 的利用率 < 1/5，则自产 A 不如从市场外购——因为要弥补这个差距需要把 B 的建筑升到 A 的5倍以上等级，指数成本完全不合算。

---

### 迭代收敛法（Iterative Convergence）

**核心问题**：单轮利用率计算是错误的。当某个节点被判定为外购后，该建筑停止运行，其对上游的消耗也随之消失，导致上游节点的利用率下降，可能引发连锁外购。必须迭代计算直到稳定。

**算法**：
```
1. 初始集合 active = 全部链内节点
2. 计算每个节点的利用率（只统计 active 集合内的下游消耗）
3. 将利用率 < 0.2 的节点（目标产品除外）标记为外购，从 active 中移除
4. 若本轮有移除 → 回到步骤2
5. 若本轮无移除 → 收敛，输出最终自产/外购集合
```

**实现**：`chain_util.js` 已内置此逻辑，运行后输出每轮迭代详情。

**典型案例（Satellite）**：
- 第1轮：外购 Attitude Control、Flight Computer、Golden Bars、Water
- 第2轮：Attitude Control/FC 外购 → Electric Motor、OBC、Gold Ore 消耗归零 → 也外购
- 第3轮：Electric Motor/OBC 外购 → Steel、Processors、EC 消耗归零 → 也外购
- 第4轮：Steel 外购 → Iron Ore 归零；Silicon 仅剩一路消耗降至 0.047 → 也外购
- 第5轮：Silicon 外购 → Sand 归零 → 也外购
- 第6轮：收敛。**自产从15个节点崩塌至5个**

**重要结论**：单轮分析会严重高估可自产节点数。链条越宽、产品越低频，连锁效应越强。

**调整方式（利用率在 0.2~0.5 之间时）**：
- 不必非得提升 B 的等级：可以适当**降低 A 的建筑数量**（比如只建1座A而非2座）
- 或者 A 多余的产出**卖给市场**作为副产品收入
- 目标：让实际流向 B 的比例 ≥ 50%

---

### 维度三：流量匹配（Flow Balance）

对链条中每条边 A → B（每生产1单位B需要q单位A）：

```
流量比 = 生产B所需的A产量 / A建筑的自然产出量
```

- 流量比 ≈ 1：上下游几乎完全对接，无浪费
- 流量比 << 1：上游产能严重过剩，A需要同时向市场销售（增加运营复杂度）
- 流量比 >> 1：下游消耗超过上游供给，上游成为瓶颈

**原则**：链条中所有边的流量比应在 `0.3 ~ 3` 之间，极端值意味着该环节事实上是市场采购而非自产。

---

### 维度四：瓶颈建筑（Bottleneck）

每条链都有一个产能最低的建筑类型，它决定了整条链的上限。
选链时优先选择**瓶颈建筑产出的是最终高价值产品**的链条，而不是瓶颈卡在中间环节。

---

### 选链策略（三步法）

**第一步：枚举候选终点**
- 列出所有叶节点（最终产品）
- 计算每个叶节点的完整依赖树的产品节点数
- 筛选：依赖树节点数在 **8~20** 之间（太少深度不够，太多需大量外购）

**第二步：按预算裁剪（Budget Pruning）**
- 若依赖树节点数 > N（如 >12），需裁剪
- 裁剪策略：从根部（靠近 Power 的节点）开始切断，改为外购
- 记录被切断的节点数 = **外购依赖数**（越少越好）

**第三步：按综合分数排名**
```
Score = L × (N_self / N_total)
```
- `L`：链条深度（Power到最终产品的层数）
- `N_self`：自产节点数（不超过预算 N）
- `N_total`：完整依赖树节点数
- `N_self / N_total`：自给率（越高越好，= 垂直整合程度）

**简化版（预算内直接比较）**：
```
Score = L    （在节点数 ≤ N 的前提下）
```
即：在能自产的条件下，单纯比深度。

---

### 投资路径策略（分阶段）

建议从链条**底部开始投资**，逐步向上整合：

1. **阶段1**：先建/升级最底层建筑，稳定供应中间品→卖给市场
2. **阶段2**：有盈余产能后，建下一层建筑，消化上游产出
3. **阶段3**：链条稳定后，重点升级**瓶颈建筑**，整体产能随之提升

---

## 待补充的指标维度

### A. 建筑宽度惩罚
- 统计产业链依赖树中涉及的**不同建筑类型数量**（`B`）
- 改进评分：`L × I / B`

### B. 流量匹配度
- 对产业链每条边 A→B，计算消耗比：`需求量 / 产出量`
- 若比值远小于1（如0.1），说明上游大量剩余，产业链不平衡
- 可定义流量失衡惩罚：取所有边中最小消耗比作为惩罚系数

### C. 投资回报
- 需要价格数据：最终产品市价 vs 原料总成本
- 需要 simcotools API 数据（见下节）

#### Realm 参数
- 当前使用 realm = **`0`**（标准realm）

#### 响应数据结构

**VWAP** `GET /v1/realms/0/market/vwaps/{resource}`
```json
{
  "vwaps": [
    { "resourceId": 1, "quality": 0, "datetime": "2026-03-11T00:00:00Z", "vwap": 0.282 }
    // quality 0~12，每个品质一条记录
  ]
}
```

**资源详情** `GET /v1/realms/0/resources/{resource}`
```json
{
  "phase": "normal",
  "resource": {
    "id": 1,
    "name": "Power",
    "producedAnHour": 2566.94,   // ← 该realm每小时总产量（流量分析关键字段）
    "wages": 414,                 // 工资成本
    "inputs": {}                  // 生产配方，原料ID→用量（Power为空）
  }
}
```

#### 分析用途规划
- **利润率计算**：用 VWAP（quality=0 基准品质）计算产业链理论利润 = 最终产品价 - Σ(原料价 × 用量)
- **流量匹配**：用 `producedAnHour` 对比上下游实际产量，验证链条是否平衡
- **市场深度**：用 candlesticks 判断价格稳定性，避免选择波动过大的产品
- **竞争分析**：用 `stats/buildings` 了解各类建筑数量，评估供给侧竞争压力
- **经济相位**：用 `phases` 判断当前扩张/衰退期，影响产品选择
